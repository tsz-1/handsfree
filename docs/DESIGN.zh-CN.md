# 设计笔记：每个决定背后的原因

这份文档按"问题 → 原因 → 解决 → 数字"的顺序解释项目里的关键设计。数字都来自 `reports/` 里的实测结果。

## 1. 为什么教程版会连点，状态机怎么解决

**现象。** 教程版每一帧都检查"拇指和食指尖距离是否小于阈值"，小于就调用 `click()`。摄像头 30–47 帧每秒，捏合动作至少持续 0.2 秒，于是一次捏合产生 6–10 次点击。加个"距离大于阈值时重置"的标志只能治标：手指在阈值附近抖动时，标志会反复翻转，仍然多次点击。

**根因。** 把"每一帧的姿态"直接当成"用户的意图"。姿态是连续量，意图是离散事件，中间缺一个把连续信号变成离散事件的层。

**解决。** `gestures.py` 里的 `GestureInterpreter` 是一个显式状态机：`IDLE → PINCH → (释放) 发出 CLICK → IDLE`，或者 `PINCH → (超过 0.3 秒) DRAG，发出 MOUSE_DOWN → (释放) MOUSE_UP`。点击在**释放时**发出，而且每次状态转移只发一个事件，所以一次捏合无论持续多久都恰好对应一次点击或一次拖拽。滚动和右键是同一个状态机里的另外两条分支。

**附带的好处。** 状态机把"识别"和"执行"分开了：`GestureInterpreter` 只输出 `Intent` 列表，`MouseController` 才去碰 pyautogui。所以状态机可以用合成的手数据做单元测试（`tests/test_gestures.py`），不需要摄像头，也不会真的动鼠标。

## 2. 为什么用 One Euro Filter，而不是固定系数的指数平滑

**固定系数的问题。** 指数平滑 `p += (x - p) / 8` 只有一个参数，同时控制抖动和延迟：系数小则稳但慢，系数大则快但抖。光标恰恰同时需要两者：停在按钮上时要稳，扫过屏幕时要快。

**One Euro 的思路**（Casiez 等，CHI 2012）。还是一阶低通，但截止频率随速度变化：`cutoff = min_cutoff + beta * |速度|`。手静止时速度约为零，截止频率取最低值 `min_cutoff`（0.5 Hz），平滑最强；手快速移动时截止频率线性升高，滤波器几乎不再滞后。速度本身也经过一个低通（`d_cutoff`）避免噪声把截止频率顶高。实现只有 20 行，见 `filters.py`。

**数字**（`tools/benchmark.py`，`reports/smoothing_tradeoff.png`）。用真实录下的静止轨迹算抖动（相邻帧光标位移的 RMS），用同一份滤波代码算 1800 px/s 匀速目标的滞后：

| 平滑 | 抖动 (px/帧) | 滞后 (px) |
| --- | --- | --- |
| 无 | 6.5 | 0 |
| 指数 ÷8（教程默认） | 3.4 | 420 |
| One Euro（当前配置） | 5.1 | 22 |

单看一行不公平，所以对两种滤波各扫一遍参数。在同样 4.4 px 的抖动下，指数平滑滞后 180 px，One Euro 67 px；同样约 30 px 的滞后下，指数平滑抖 5.7 px，One Euro 5.1 px。曲线整体在左下方，说明这不是调参差异，而是方法差异。

**为什么不把抖动压到更低。** 手悬空本来就有每帧几个像素的真实颤抖。把 `beta` 调小可以把抖动压到 4.0，但滞后升到 100 px，点小按钮时会感觉光标"跟不上手"。当前配置故意选在低延迟那一端。

**面试追问：如果换成卡尔曼滤波？** 卡尔曼需要运动模型和噪声协方差，手的运动没有好的先验模型，调参更难；One Euro 两个参数就有直观含义（静止时多稳、动起来多快），对交互场景更合适。这也是它在 VR/AR 手部追踪里被广泛使用的原因。

## 3. 为什么捏合阈值要按手掌尺寸归一化

**问题。** 教程版阈值是像素（例如 "距离 < 40 px"）。手靠近摄像头一倍，所有距离在图像里放大一倍，同样的捏合动作可能不再触发；离远则轻轻一碰就触发。

**解决。** 用"手腕到中指根部"的距离作为手掌长度，所有距离除以它。捏合判断变成 "拇指尖到食指尖距离 / 手掌长度 < 0.30"，这是一个无量纲比值，与距离、分辨率都无关。

**迟滞。** 进入阈值 0.30，退出阈值 0.40。比值在 0.30–0.40 之间时保持当前状态，手指在边界抖动不会反复触发。这和恒温器、施密特触发器是同一个思路。

**防止握拳被当成捏合。** 握拳时拇指和食指也很近。所以进入捏合还要求食指是伸出的：食指尖到手腕距离 / 手掌长度 > 1.2（伸直大约 2，握拳小于 1）。这个值也是归一化的。

## 4. 点击位置的修正：click rewind

**问题。** 捏合时食指尖会向拇指方向移动一两厘米，光标跟着食指尖，于是点击落在目标旁边。

**解决。** `MouseController` 保留最近 1 秒的光标位置历史。点击事件携带捏合**开始**的时间戳，执行时取"开始前 0.15 秒"的位置。这个时刻手指还没开始并拢，光标还在用户瞄准的位置。0.15 秒是实测：太短修不干净，太长会取到还在移动中的位置。

## 5. 分类器的特征怎么设计

**输入。** MediaPipe 的 21 个关键点像素坐标。直接用像素坐标，模型会学到"手在画面哪个位置、多大、朝哪边"，这些和手势无关，换个位置就失效。

**归一化三步**（`classifier.py: hand_features`）：

1. **平移**：所有点减去手腕坐标。手在画面里的位置不再影响特征。
2. **缩放**：除以手掌长度（手腕→中指根）。远近不再影响。
3. **旋转**：把"手腕→中指根"这个向量旋转到竖直向上。手倾斜不再影响。

再加一步**镜像**：如果食指根部在小指根部的右侧，把 x 取反。这样左右手、以及手掌翻转朝向都映射到同一种表示。为什么不用 MediaPipe 的左右手标签？实测它在手转动时会跳变，用关节几何来判断更稳定。

最终 42 维特征（21 个点 × 2），逻辑回归即可。

**旋转归一化是实测出来的。** 第一版特征只做了平移和缩放，留一会话交叉验证只有 45%。用 `tools/dataset.py check` 查数据发现两件事：一个会话里 4 个手势按错了键（用 `relabel` 修正），以及不同会话手的倾斜角度不同。加入旋转归一化后升到 87%。

## 6. 为什么用留一会话交叉验证，而不是随机划分

数据是连续视频帧，相邻帧几乎一样。随机划分会把同一秒的帧同时放进训练集和测试集，测试等于在背答案：随机划分 98.4%，留一会话（训练两个会话，测试第三个）86.8%。差 12 个百分点。

真实使用时模型面对的是新的一次坐下、新的光线、新的距离，正好对应"新会话"。所以 86.8% 才是能兑现的数字，README 里只报这个。

同样的原因，模型选择也按留一会话的宏 F1 来选。四个模型里逻辑回归最好（86.8%），同时推理最快（0.08 ms/帧），随机森林 200 棵树要 3.9 ms，不值得。

## 7. 怎么防止快捷键误触发

误触发比漏触发贵得多：漏了再做一次，误了可能截屏或切走窗口。所以在分类器之后有五道闸门（`app.py` 主循环 + `shortcuts.py`）：

1. **概率平滑**：对分类器输出做指数平滑（系数 0.6），单帧的错误预测被冲淡。
2. **置信度阈值**：平滑后的最高概率 ≥ 0.8 才算候选。
3. **保持时间**：候选姿态需要连续保持 0.4 秒才触发，触发后必须换手势或松开才能再触发（每次保持只触发一次），另有 1 秒冷却。
4. **运动闸门**：手腕速度（按手掌长度归一化）超过 1.5 掌长/秒时不认。刻意的手势是停下来做的，手在移动中出现的"像某个手势"的姿态是过渡态。
5. **在画面内 + 鼠标状态为 IDLE**：手部分出画面时 MediaPipe 会猜测看不见的关键点，经常猜成握拳；正在捏合或滚动时也不响应快捷键。

此外有**难负例挖掘**：运行时误触发了就按 `n`，程序把最近 1.5 秒的关键点存成 `none` 类，重新训练后模型就学会了"这个过渡姿态不是任何手势"。

线下回放录制数据：`none` 类片段 0 次误触发/分钟，22 个真实手势片段中 20 个成功触发。

## 8. Benchmark 的数字是怎么测的

`tools/benchmark.py`，摄像头实测，分两段：

- **延迟和 FPS**：正常使用 20 秒，用 `perf_counter` 记录每帧的读取、检测、逻辑三段耗时，报 p50 和 p95（p95 比平均值更能反映卡顿）。结果 21 / 24 ms，47.5 FPS。瓶颈是摄像头读取 13 ms，MediaPipe 7.6 ms，自己的逻辑 0.2 ms。
- **抖动**：手伸食指静止 5 秒，记录**未滤波**的指尖屏幕坐标和时间戳，去掉前 1 秒热身，然后把三种滤波分别作用在**同一份**轨迹上。度量是相邻帧位移的 RMS，而不是"到均值的距离"——后者会把手的缓慢漂移算进去，而 One Euro 的设计就是保留慢速真实运动，用那个度量会得出错误结论。第一版就是这么错的，改了以后才合理。
- **滞后**：用合成的 1800 px/s 匀速轨迹（约一秒扫过屏幕）算 2 秒后滤波输出和真值的差。标明是合成，因为真实场景里没有"真值"可比。

原始轨迹存在 `benchmark.json` 里，所以 `plot_benchmark.py` 可以离线重算，换度量不用重录。

## 9. 其他可能被问到的

**为什么用 scikit-learn 不用 PyTorch？** 42 维特征、几千个样本、6 个类，逻辑回归就到 87%，深度模型没有数据支撑，而且推理 0.08 ms 没有任何部署负担。工具要匹配问题规模。

**为什么用 MediaPipe 而不是自己训检测器？** 手部关键点检测是成熟问题，MediaPipe 在 CPU 上 7.6 ms。项目的价值在关键点之后的交互层和 ML 流程，不在重造检测器。

**没有摄像头怎么测试？** `tests/handgen.py` 用几何方式生成 21 个关键点的合成手（伸哪几根指、是否捏合、缩放、平移、左右手），状态机、特征不变性、动作执行都用它测，pyautogui 用 stub 替换。47 个测试在 CI 的 Ubuntu 上无头运行。

**遇到的最麻烦的 bug？** 两个 pyautogui 在 macOS 上的问题，dry-run 阶段发现不了：(1) `dragTo(mouseDownUp=False)` 会把默认的 `"primary"` 直传给系统后端触发断言，拖拽必崩，修法是显式传 `button="left"`；(2) macOS 的双击不是按时间推断的，鼠标事件自带"第几次点击"字段，pyautogui 从不设置它，所以两次单击永远不构成双击，最后绕过 pyautogui 直接用 Quartz 发事件并写入点击次数。

**接下来会做什么？** 按优先级：多人数据集验证分类器的跨用户泛化；动态手势（挥手翻页）需要时序模型；把 One Euro 参数做成运行时校准而不是改 YAML；Windows 上的双击和媒体键。
